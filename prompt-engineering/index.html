🔹 Fundamentals of Prompt Engineering

Prompt Engineering is the process of designing, structuring, and optimizing inputs (prompts) given to Large Language Models (LLMs) to obtain accurate, consistent, useful, and controllable outputs.

Traditional Programming : Input → Logic → Output
LLM Programming : Prompt → Model Reasoning → Output

Sample Prompt

          You are a senior business analyst.

          Summarize the document.

          Requirements:
          1.  Maximum 200 words
          2.  Include risks
          3.  Include recommendations
          4.  Return markdown table

Output becomes:

  • Consistent
  • Structured
  • Actionable

What is Chain-of-Thought?

Chain-of-Thought prompting is a technique where the model is encouraged to solve a problem step by step instead of producing a direct answer.

🔹 Prompt Components

Prompt components typically include:

  • Role: “You are a senior data engineer”
  • Task: Review this PySpark code.
  • Context: The code runs on AWS EMR.
  • Constraints: Focus only on performance issues.
  • Output Format: Return JSON.

Best Practices of Prompt Engineering

  • Be Specific
  • Define Role
  • Define Output Format
  • Add Constraints
  • Use Delimiters
  • Provide Examples

Types of Context

Constraints

What the model should and should not do; constraints act like guardrails.

  • Maximum 200 words
  • Return JSON only
  • Do not make assumptions

Types of Constraints

  • Length Constraints
  • Format Constraints
  • Scope Constraints
  • Style Constraints
  • Safety Constraints

Relationship Between Instruction, Context, and Constraints

Instruction: Generate Spark optimization recommendations.

Context: Job processes 20 TB daily on EMR.

Constraints: Focus only on shuffle reduction. Return top 5 recommendations.

Prompt Template

Role: [Who should the model act as?]

Instruction: [What task should be performed?]

Context: [Relevant information]

Constraints: [Rules and limitations]

Output Format: [Expected structure]

Example:

Act as a Principal Data Architect — Role
Review this Athena SQL query. — Task / Instruction

Context:
  Table size = 15 billion rows
  Partition columns: year, month, day

Constraints:
  1. Focus on performance.
  2. Focus on partition pruning.
  3. Ignore formatting.
  4. Return:
     - Issue
     - Impact
     - Recommendation

Delimiters

Delimiters are symbols, tags, or markers used to clearly separate different parts of a prompt.

  • Where instructions start
  • Where instructions end
  • Where context begins
  • Where user data exists
  • What should be analyzed

Without delimiters the core prompt components blend together, leading to hallucinations. Proper delimiters improve context handling.

The Persona Pattern

Persona Prompting means instructing the model to adopt a specific role, identity, expertise level, or perspective before performing a task.

Enterprise AI systems use personas to:

  • Control expertise
  • Control reasoning style
  • Control vocabulary
  • Control output quality
  • Control decision‑making behavior

Types of Personas: Expert Persona, Experience‑Level Persona, Audience Persona, Behavioral Persona, Multi‑Persona Prompting, Dynamic Personas.

🔹 Advanced Prompting Techniques

Tree-of-Thought (ToT) Prompting

Tree‑of‑Thought is a technique where the model explores multiple reasoning paths (branches) before selecting the best solution, enabling richer problem‑solving.

Skeleton-of-Thought (SoT) Prompting

Skeleton‑of‑Thought first generates an outline (the “skeleton”) of the answer and then expands each section, improving structure and completeness.

Program-of-Thought Prompting

Program‑of‑Thought converts the reasoning process into executable logical steps or code, allowing the model to produce programmatic solutions.

🔹 Prompt Hyperparameters

Prompt hyperparameters are configuration values that influence how a language model generates tokens.

  • Temperature – Controls creativity by scaling the probability distribution. Higher values increase randomness.
  • Top‑P (nucleus sampling) – Limits selection to the smallest set of tokens whose cumulative probability exceeds P.
  • Top‑K – Restricts token choices to the K most likely candidates.
  • Max Tokens – Caps the maximum number of tokens the model may produce.
  • Stop Sequences – Specifies strings that, when generated, cause the model to stop (e.g., a semicolon for SQL).
  • Presence Penalty – Encourages the model to introduce new topics or ideas.
  • Frequency Penalty – Reduces repetition by lowering the probability of tokens that have already appeared.

Hyperparameter Categories

  • Creativity Controls – Temperature, Top‑P, Top‑K
  • Length Controls – Max Tokens, Stop Sequences
  • Diversity Controls – Presence Penalty, Frequency Penalty

Generation Flow

Model predicts probabilities
↓
Temperature reshapes distribution
↓
Top‑K / Top‑P filter candidates
↓
Final token is sampled

Penalty Illustrations

Frequency Penalty – Reduces the likelihood of tokens that appear many times.

Presence Penalty – Reduces the likelihood of tokens that have appeared at least once, promoting topic diversity.

No penalty          :  Cloud computing is scalable. Cloud computing is flexible. Cloud computing is cost‑effective.
Frequency penalty   :  Cloud computing is scalable, flexible, and cost‑effective.
Presence penalty    :  Cloud computing provides scalability, global accessibility, automation, and improved resilience.

🔹 Prompt Tuning & Evaluation

Prompt parameter tuning is the process of finding optimal values for the hyperparameters.

Why needed: LLMs are probabilistic systems, not deterministic programs.

Prompt Engineering = Design + Parameters + Evaluation

Evaluation: If prompt tuning is engineering the system, then prompt evaluation is measuring whether it actually works in the real world.

Prompt evaluation assesses the quality, correctness, and reliability of LLM outputs produced by a prompt + parameter configuration.
